# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a personal academic website for Pingfan Hu, built with **Quarto** (a scientific publishing system). The site is deployed to `pingfanhu.com` and uses R for dynamic content generation.

## Build Commands

```bash
# Preview site locally (live reload)
quarto preview

# Build the full site
quarto render

# Render a single file
quarto render about.qmd
```

The rendered output goes to `_site/`. CV and Resume are rendered as PDF via a custom `cv-pdf` format defined in `_extensions/`.

Local R dependencies (install once): `tidyverse`, `htmltools`, `commonmark`, `kableExtra`, `here`, `surveydown`.

## Architecture

### Site Configuration
- **`_quarto.yml`** — master config: navbar, theme, CSS, global R chunk options, resource paths. Also excludes `**/resources/*.qmd` from rendering at the project level.
- **`_variables.yml`** — reusable shortcodes like `{{< var rnolink >}}` and `{{< var sloan >}}` used site-wide
- **`styles/styles.scss`** — custom SCSS on top of the `flatly`/`darkly` Bootstrap themes, background `#F8F7F0`
- **`styles/styles.js`** — injected after body on every page via `_quarto.yml`. Responsibilities: dynamic footer year, scroll fade-in animations (via IntersectionObserver on `.quarto-post`, `.quarto-grid-item`, `.presentation-box`; the reveal is **one-shot** — once a card's fade-in transition ends the JS removes the `animate-on-scroll`/`is-visible` classes so they stop owning `transform`/`transition`, which is what lets the cards' hover-glow and `:active` press effects work), the **"Back to &lt;Section&gt;" pill** injected above the title on subpages (`.subpage-back-btn`), language labels above code blocks, copy-button UX cleanup, and the **recipe step timer** (scoped to `/recipes/` paths): each step's `.step-time` chip becomes a clickable countdown drawer that mounts in-flow under the card, auto-scrolls into view (desktop centers the card+drawer; mobile pins the drawer's bottom just above the fixed footer, in absolute coords so re-toggling never drifts), and adds a purple active-card glow while running. A floating `.recipe-timer-jump` button (bottom-right, above the footer) appears only when a timer is open and its drawer has scrolled off-screen, and taps back to the active card via the same scroll logic. Cocktail pages reuse the same `.step-*` markup but the timer is intentionally disabled there (the JS bails outside `/recipes/`).

### Content Sections
- **`index.qmd`** — homepage (trestles layout)
- **`about.qmd`**, **`blog.qmd`**, **`projects.qmd`**, **`papers.qmd`**, **`talks.qmd`** — top-level pages
- **`cv.qmd`** / **`resume.qmd`** — rendered as PDF using `format: cv-pdf`
- **`recipes.qmd`** — personal recipe collection (Chinese). Grid listing reads from `recipes/`. Linked from the navbar 杂记 menu.
- **`cocktails.qmd`** — personal cocktail collection (Chinese). Grid listing reads from `cocktails/`. Linked from the navbar 杂记 menu.

### Reusable Chunks (`chunks/`)
Partial `.qmd` files included via `{{< include /chunks/filename.qmd >}}`:
- `intro.qmd`, `skills.qmd` — used in both `index.qmd` and `about.qmd`
- `2025-plosone-surveydown.qmd`, `2025-erl-smart-charging.qmd`, etc. — paper citation blocks reused across `papers.qmd` and project pages

### Content Collections
- **`blog/`** — individual blog posts, each in their own subdirectory with an `index.qmd`. Listing auto-generated by `blog.qmd`.
- **`projects/`** — research project pages, same pattern. Listing auto-generated by `projects.qmd` as a grid.
- **`recipes/`** — individual recipe pages (Chinese), one subdirectory per recipe with an `index.qmd`. Listing auto-generated by `recipes.qmd` as a grid. Banner images live in `recipes/banners/`. All recipe **content** should be written in Chinese, but all **filenames** (recipe subdirectory names, `.qmd` filenames if any, and banner image filenames) must be in **English only** — no pinyin, no Chinese characters. Example: `recipes/tomato-beef-brisket/index.qmd` with banner `recipes/banners/tomato-beef-brisket.png`.
- **`cocktails/`** — individual cocktail pages (Chinese), one subdirectory per cocktail with an `index.qmd`, structurally identical to recipes. Listing auto-generated by `cocktails.qmd` as a grid. Banner images live in `cocktails/banners/`; reusable ingredient icons in `cocktails/resources/{base,mixer,garnish}/`; the five glass paradigm source images in `cocktails/example-banners/`. Cocktail pages reuse the recipe component CSS (`.recipe-*`, `.ing-*`, `.timeline-*`, `.step-*`, `.pairing-*`) — no separate SCSS. Use the **`/ph-cocktail`** skill to scaffold a new cocktail (the drink-world twin of `/ph-recipe`). Same English-filename / Chinese-content rule as recipes. Example: `cocktails/mojito/index.qmd` with banner `cocktails/banners/mojito.png`.
  - **`cocktails/pantry/index.qmd`** (原料图鉴) is a special **non-drink** reference page that catalogs every ingredient icon (基酒 / 调味 / 装饰) from `cocktails/resources/`. It follows the same thin-index + `html/` include pattern as a cocktail page (`html/{base,mixer,garnish}.qmd`, plus `html/_metadata.yml` with `draft: true`), but the three `.ing-outer` sections are wrapped in a centered `.pantry-page` div (the wrapper opens in the index's first `{=html}` block and closes in the last, with the includes between). It is surfaced on `cocktails.qmd` as a hero feature banner (`.pantry-hero`, art at `cocktails/banners/pantry-hero.png`) **above** the grid — not as a grid card — and is kept out of the grid listing by a negation glob: `listing.contents: [cocktails, "!cocktails/pantry/index.qmd"]`. The banner markup itself lives in `chunks/cocktails-pantry-hero.qmd` and is pulled into `cocktails.qmd` via `{{< include /chunks/cocktails-pantry-hero.qmd >}}`.
- **`talks/talks.csv`** — data-driven talks listing. `talks.qmd` reads this CSV with R (`tidyverse`, `htmltools`, `commonmark`) and generates HTML cards. Adding a new talk = adding a row to the CSV. Columns: `Date`, `Title`, `Event` (supports markdown links), `Location`, `Name`, `Type`. `Type` must be `"slide"` or `"poster"` — slides get three buttons (Slides, PDF, GitHub) linking to `https://pingfan-hu.github.io/{Name}/` and `/talks/{Name}.pdf`; posters get only a PDF button.

### Extensions (`_extensions/`)
- `cv/` — custom LaTeX format for PDF CV generation
- `quarto-ext/` — additional Quarto extensions (e.g., fontawesome icons used as `{{< fa brands r-project >}}`)

## Standards and Rules

All component design standards live in `.claude/rules/`. Always consult the relevant rule before creating or modifying a styled HTML component or image:

| Rule file | Covers |
|-----------|--------|
| `html-table-description.md` | 2-column label → value tables with icons, mobile stacking |
| `html-table-icon.md` | Icon card grid with centered header and optional section bars |
| `html-button-table.md` | Label + pill button rows (`.lnk-*` classes) |
| `html-button-intro.md` | Centered intro pill buttons (`.intro-links` / `.intro-btn`) |
| `html-url.md` | URL anatomy diagrams with overflow detection |
| `image-banner.md` | Blog/project banner generation via claude-image-gen |
| `image-nav.md` | Section nav card images |
| `image-embedding.md` | Embedding images in blog posts (bordered, captioned) |

## Key Conventions

- **Project pages**: Each project lives in `projects/{year}-{slug}/index.qmd`. Front matter includes `title`, `image`, `author`, `date`, `categories`, and `description`.
- **Blog posts**: Same pattern in `blog/{date}-{slug}/index.qmd`. `_metadata.yml` in `blog/` sets `author: "Pingfan Hu"` globally for all posts.
- **Banners**: Project/blog banner images live in `projects/banners/` and `blog/banners/` (referenced in listing configs).
- **External links**: `link-external-newwindow: true` is global; internal links are filtered by `pingfanhu.com` domain.
- **`{{< include >}}`** paths are always absolute from project root (e.g., `/chunks/intro.qmd`).
- **Intro buttons** (2–4 project links at the top of a post): write HTML directly in the `.qmd` using `.intro-links` / `.intro-btn` classes — CSS is global in `styles.scss`, no `<style>` block needed. See `.claude/rules/html-button-intro.md`.
- **Link tables** (label + multiple buttons): use `.lnk-outer` / `.lnk-row` / `.lnk-btn` with color variants `lnk-purple`, `lnk-blue`, `lnk-green`, `lnk-orange`. CSS is global in `styles.scss`. See `.claude/rules/html-button-table.md`.
- **Styled HTML components in blog posts**: Use `{{< include resources/filename.qmd >}}` to embed styled HTML tables or visuals. The included file must be a `.qmd` (not `.html`) with content wrapped in a ```` ```{=html} ```` fence. Store these files in a `resources/` subdirectory within the post folder. Do NOT use iframes. See `.claude/rules/html-table-description.md` or `.claude/rules/html-table-icon.md` for the full design standards.
- **Styled HTML components in recipe and cocktail pages**: Same pattern as blog posts, but the subdirectory is named `html/` instead of `resources/` (semantically clearer for recipe/cocktail-specific HTML blocks). Example: `recipes/tomato-beef-brisket/html/ingredients.qmd` is included via `{{< include html/ingredients.qmd >}}`. The `html/` folder needs its own `_metadata.yml` with `draft: true` (same as `resources/`), and the project-level `_quarto.yml` excludes both `**/resources/*.qmd` and `**/html/*.qmd` from rendering.
- **Banner image generation**: Always use the claude-image-gen CLI to generate banner images. Never use Pillow or HTML/CSS rendering. See `.claude/rules/image-banner.md` for the full workflow, prompt template, and style standard. **Never write the Gemini API key as a literal value anywhere** — it lives in `~/.zshrc` as `$NANOBANANA_GEMINI_API_KEY`.
- **`resources/` and `html/` subdirectories**: Every such folder inside a post or recipe must contain a `_metadata.yml` with `draft: true` to prevent Quarto's listing from picking up the component `.qmd` files. (The project-level `_quarto.yml` also globally excludes `**/resources/*.qmd` and `**/html/*.qmd` from rendering as a second guard.)
- **`projects/_metadata.yml`**: Hides the title metadata block for all project pages via injected CSS.
- **Blog post citations**: Posts can include a `references.bib` file in the post folder for Quarto-rendered citations.
- **Card & button interactions** (kept consistent site-wide): every listing card (`.quarto-grid-item`, `.quarto-post`) and the cocktails pantry hero (`.pantry-hero`) shares one hover/press language — a soft glow + border brighten on `:hover` (**no lift / no `translateY`**) and a subtle `transform: scale(0.992)` press on `:active`. All HTML-generated buttons (`.intro-btn`, `.lnk-btn`, `.subpage-back-btn`, `.post-nav-btn`, `.presentation-button`, paper `.btn-outline-primary`) get a `transform: scale(0.96)` press on `:active` (buttons that already nudge on hover, like the back/prev/next buttons, combine the nudge with the scale). When adding a new card or button, match this — do not reintroduce a hover lift. Note the pantry hero glow is a *lighter* lavender than its purple background (so the halo reads as a glow, not a blurry edge), whereas light cards/buttons glow in the accent purple `#5654A2`.
- **Theme**: supports light (`flatly`) and dark (`darkly`) modes — both share `styles/styles.scss`. Test SCSS changes in both modes.
- **TOC layout**: `_quarto.yml` sets `toc: true` with `toc-location: left` globally. Quarto reserves left-column space for the TOC. Pages that set `toc: false` in their front matter lose this reservation and their content shifts rightward. To keep content centered on no-TOC pages, use custom CSS to adjust the layout rather than simply disabling the TOC.
- **HTML indentation in `.qmd`**: Use 1-space indentation per level in raw HTML blocks. Pandoc treats 4+ leading spaces as a code block, which silently breaks inner `<div>` elements.

## Deployment

CI runs on every push to `main` via `.github/workflows/build.yml`. It installs R 4.3.2 with packages `tidyverse`, `kableExtra`, `here`, and `surveydown`, then runs `quarto render` and deploys to Netlify. The `SITE_PASSWORD` secret is passed as an environment variable during render.
